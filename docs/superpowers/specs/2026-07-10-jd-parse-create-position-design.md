# JD 单生成岗位 — 产品设计（方案 A）

- **日期**：2026-07-10
- **状态**：已确认方案 A，待审阅后写实现计划
- **范围**：设计文档 only，不含实现代码

---

## Overview

在项目管理页的「岗位列表」Tab，组长/系统管理员可粘贴一段 JD 原文，由 AI 解析出岗位字段并预填到现有「创建岗位」弹窗。用户核对、补选所属客户与项目后，再走现有创建接口落库。

核心原则：**AI 只辅助填表，不代替人决策；公司/项目必须人工选择；最终确认后才保存。**

---

## Goals

1. 减少创建岗位时的手工录入：从 JD 文本自动抽出可映射字段并预填。
2. 复用现有「创建岗位」弹窗与 `POST /api/positions`，不另建一套保存链路。
3. 权限与「新建岗位」一致：仅组长与系统管理员可用。
4. 解析失败时明确提示，不打开创建弹窗，避免半成品状态。

---

## Non-Goals（本版不做）

- 不支持上传 Word / PDF（仅粘贴纯文本）。
- 不由 AI 推断或自动选择所属客户、所属项目。
- 解析完成后不直接落库；必须经用户确认「创建」。
- 不在本流程中自动匹配/锁定简历。
- 不改岗位锁定上限（固定 10）。

---

## User Flow（方案 A）

```text
岗位列表 Tab
  → 点击「📎 JD单生成岗位」
  → 打开 JD 粘贴小弹窗（多行输入 + 开始解析 / 取消）
  → POST /api/positions/parse-jd
  → 成功：关闭小窗 → 打开现有「创建岗位」弹窗并预填
  → 用户核对字段，人工选择客户与项目
  → 点「创建」→ 现有 POST /api/positions 保存
  → 失败：Toast 提示，不打开创建弹窗
```

步骤说明：

1. **入口**：`src/pages/projects.html` 岗位列表 Tab 上的「📎 JD单生成岗位」按钮（当前为 `data-action="noop"` 空壳）。
2. **粘贴**：小弹窗提供多行文本框，交互风格对齐简历池「AI检索 / JD 粘贴」类弹窗（多行输入 + 主操作「开始解析」+「取消」）。
3. **解析**：前端调用新接口，传入整段 `jd_text`，等待返回字段 JSON。
4. **预填**：解析成功后关闭小窗，打开现有 `[data-position-modal]`「创建岗位」弹窗，按 Field Mapping 写入控件；客户/项目保持空，需用户选择。
5. **保存**：用户确认后走现有创建逻辑，不新增第二条保存路径。

## API

### `POST /api/positions/parse-jd`

**用途**：仅解析 JD 文本为可预填字段，**不写库**。

**鉴权**：与创建岗位一致——登录用户且角色为组长或系统管理员；操作员返回 403。

**Request**

```json
{
  "jd_text": "……完整 JD 原文……"
}
```

| 字段 | 类型 | 约束 |
|------|------|------|
| `jd_text` | string | 必填；去空白后非空；建议服务端设合理长度上限（实现计划再定具体值） |

**Response（200）** — 字段 JSON，供前端预填：

```json
{
  "name": "高级 Java 工程师",
  "description": "……与请求中 jd_text 一致的整段原文……",
  "urgency": "紧急",
  "hiring_count": 2,
  "salary_min": 20,
  "salary_max": 35,
  "location": "上海",
  "age_requirement": "30-40岁",
  "gender_requirement": "不限",
  "education_requirement": "本科",
  "experience_requirement": "5年以上",
  "job_status_requirement": "不限"
}
```

说明：

- `description` 固定为用户粘贴的整段原文（服务端原样回传或前端直接用输入框内容均可；推荐前端用原文写入 JD 框，避免 LLM 改写）。
- 枚举类字段必须落在下方 Field Mapping 给定选项内；无法映射时返回空字符串或「不限」（见映射表）。
- 数值类字段无法可靠解析时返回 `null`，前端保持空或默认。

**错误**

| 情况 | 行为 |
|------|------|
| 未登录 / 无权限 | 401 / 403 |
| `jd_text` 为空 | 400 + 明确文案 |
| LLM 调用失败 / 超时 / 非 JSON | 502 或 500 + 可读文案；前端 Toast，不打开创建弹窗 |
| 解析结果完全不可用（如无岗位名称且无任何可填字段） | 可由实现计划细化；至少 Toast，不打开创建弹窗 |

### 保存（不变）

- 用户确认后：现有 `POST /api/positions`。
- `target_resume_count` 仍由后端强制为 `POSITION_LOCK_LIMIT`（10）。

### LLM 复用

- 复用现有基础设施：`get_openai_client` / `call_llm_for_json`（或同等封装）。
- Prompt 约束：
  1. 只抽取岗位字段，**禁止**推断公司名、项目名或客户 ID。
  2. 枚举值必须从给定选项中选择；对不上则空或「不限」。
  3. 薪资统一为月薪 K 数值（与创建弹窗「薪资范围 (K)」一致）。
  4. 不改写 JD 原文作为 `description` 的权威来源（原文由前端保留）。

## Field Mapping

### 预填总览

| 创建弹窗字段 | 数据来源 | 规则 |
|--------------|----------|------|
| 所属客户 | 不预填 | 人工选择（必选） |
| 所属项目 | 不预填 | 人工选择（必选，先选客户） |
| 岗位名称 | AI | 从 JD 标题/首行/「岗位名称」等抽取；抽不到则空，用户必填 |
| 岗位 JD | 原文 | 整段粘贴原文，不经 AI 改写 |
| 紧急程度 | AI | 映射到弹窗选项；对不上则默认「正常」 |
| 招聘人数 | AI | 正整数；抽不到则保持默认 `1` 或空（与现有打开弹窗默认一致时用 `1`） |
| 薪资下限 / 上限 (K) | AI | 数字；抽不到则空 |
| 工作地点 | AI | 文本；抽不到则空 |
| 年龄规则 | AI | 枚举映射；对不上 →「不限」 |
| 性别规则 | AI | 枚举映射；对不上 →「不限」 |
| 学历要求 | AI | 枚举映射；对不上 →「不限」 |
| 工作经验 | AI | 枚举映射；对不上 →「不限」 |
| 求职状态 | AI | 枚举映射；对不上 →「不限」 |
| 岗位锁定上限 | 固定 | 只读 `10`，本流程不改 |

### 枚举选项（与创建弹窗一致）

| 字段 | 允许值 |
|------|--------|
| 紧急程度 | `紧急`、`正常` |
| 年龄规则 | `不限`、`20-30岁`、`30-40岁` |
| 性别规则 | `不限`、`男`、`女` |
| 学历要求 | `不限`、`本科`、`大专`、`硕士` |
| 工作经验 | `不限`、`应届生`、`1-3年`、`3-5年`、`5年以上` |
| 求职状态 | `不限`、`离职`、`在职` |

映射原则：JD 中出现近似表述时，选最接近的一项；无法落入上表则填「不限」（紧急程度除外，默认「正常」）。

### 已知现状（实现时注意）

- 创建弹窗紧急程度选项为「紧急 / 正常」；列表筛选与部分展示使用「高 / 中 / 低」。本功能预填以**创建弹窗选项**为准。
- 列表展示处已有 `urgency === '高' ? '紧急' : '常规'` 一类映射；本版不借机统一全站紧急程度枚举，除非实现计划单独排期。

## Error Handling

| 场景 | 处理 |
|------|------|
| 未粘贴内容点解析 | 前端校验，Toast「请先粘贴 JD」 |
| 解析接口 4xx/5xx | Toast 错误信息；保留小窗；**不**打开创建弹窗 |
| 网络超时 | Toast；不打开创建弹窗 |
| 解析成功但岗位名称为空 | 仍可打开创建弹窗预填其余字段；用户须补全名称后才能创建（沿用现有必填校验） |
| 创建时未选客户/项目 | 沿用现有校验：「请先选择客户、项目并填写岗位名称」 |

---

## Out of Scope

- Word / PDF / 图片 OCR 上传解析
- AI 自动匹配客户、项目
- 解析成功后静默创建岗位
- 创建后自动推荐/锁定候选人
- 修改锁定上限或恢复关键词自动匹配
- 全站统一紧急程度枚举（高/中/低 vs 紧急/正常）
