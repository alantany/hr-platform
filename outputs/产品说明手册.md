## 1. 产品概述

### 1.1 产品定位

**猎头招聘交付系统**是一套面向猎头公司内部使用的**岗位全生命周期交付管理系统**。

系统核心不是「看看板」，而是把招聘交付做成可跟踪、可协作、可审计的闭环：

```text
客户需求进入 → 项目/岗位拆分 → 简历池筛选 → 推荐与锁定
→ 面试推进与评价 → 入职确认 → 质保跟踪 → 统计复盘
```

### 1.2 目标用户

| 角色 | 典型职责 |
|------|----------|
| 超级管理员 | 账号体系、权限、标签口径、质保规则、审计与系统配置 |
| 组长 | 建客户/项目/岗位、分配岗位、看团队交付与绩效 |
| 操作员 | 检索简历、接受岗位、推荐候选人、写跟踪与评价、推进入职 |

### 1.3 两条业务主线

| 主线 | 方向 | 说明 |
|------|------|------|
| 需求进入 | 客户 → 猎头 | 甲方提出 JD；猎头在系统中结构化为客户 → 项目 → 岗位 |
| 交付推进 | 猎头 → 客户 | 从简历池筛选候选人，推荐、面试、评价，直至入职与质保 |

### 1.4 技术概要（阅读产品时可跳过）

- 前端：静态页面 + 共享壳层（导航、标题、权限菜单）
- 后端：FastAPI + PostgreSQL + SQLAlchemy
- 外部抓取数据落在独立 `recruit` schema；交付主数据在业务库中管理

## 2. 系统边界

### 2.1 系统负责

- 管理客户、项目、岗位、候选人、推荐、面试、评价、质保
- **消费**外部程序已下载/解析好的简历池数据
- 维护内部组织、角色、功能权限与数据范围
- 统计团队与项目交付情况
- 为 Recruit 抓取程序提供「待抓取岗位」配置，并查看每日抓取任务统计

### 2.2 系统不负责

- 上游招聘平台的爬虫实现与抓取策略本身
- 与智联等平台的直接账号对接（由外部 Recruit 程序承担）
- 简历来源生成策略（系统只读消费 + 业务侧手工导入）

## 3. 角色与权限总览

### 3.1 角色能力对照

| 能力 | 超级管理员 | 组长 | 操作员 |
|------|:----------:|:----:|:------:|
| 用户 / 角色 / 权限 / 数据权限 | ✅ | ❌ | ❌ |
| 标签字典 / 质保配置 / 操作日志 | ✅ | ❌ | ❌ |
| 新建客户、项目、岗位 | ✅ | ✅ | ❌ |
| 分配岗位给操作员 | ✅ | ✅ | ❌ |
| 简历池检索、导入、评价 | ✅ | ✅ | ✅ |
| 推荐 / 导出简历 | ✅ | ✅ | ✅（需已接受该岗位分配） |
| 统计数据范围 | 全部 | 授权范围 | 个人相关 |
| 平台岗位发布（Recruit） | 按菜单权限 | 按菜单权限 | 按菜单权限 |

### 3.2 权限模型要点

1. **功能权限**：按角色配置页面与操作（菜单动态显示）。
2. **数据权限**：可按公司 / 项目 / 岗位范围授权；与「岗位分配任务」联动。
3. **协作关键路径**：组长分配岗位 → 操作员在任务看板「接受」→ 才可对该岗位进行推荐等写操作。
4. **简历池**：检索对授权角色共享；同级流转有阻断规则，组长可穿透下属数据。
5. **单设备登录**：同一账号新登录会踢掉旧会话。

## 4. 核心业务对象

```text
客户(Company)
  └── 项目(Project)          ← 甲方某部门下的招聘包
        └── 岗位(Position)    ← 具体 JD / 招聘人数 / 薪资等
              └── 推荐(Recommendation)  ← 候选人与岗位的推进关系
                    ├── 面试跟踪 / 评价
                    └── 入职 → 质保

候选人(Candidate)  ← 简历池资源（可来自导入 / Recruit 映射 / 人工建档）
```

| 对象 | 含义 | 关键属性示例 |
|------|------|----------------|
| 客户 | 甲方公司 | 名称、联系人、电话、地址、合作周期、状态 |
| 项目 | 招聘包容器 | 所属客户、状态、等级、地点、周期 |
| 岗位 | 具体职位需求 | 紧急程度、招聘人数、薪资、地点、JD 描述、负责人 |
| 候选人 | 可匹配人才资源 | 基本信息、期望、来源、三维状态 |
| 推荐 | 候选人 × 岗位推进关系 | 推荐状态、漏斗分桶、推荐时间 |
| 评价 | 面试/推进过程留痕 | 轮次、等级、分值、内容、评价人 |
| 质保 | 入职后稳定期管理 | 入职日期、质保月数、剩余天数、状态 |
| 岗位分配任务 | 组长 → 操作员协作 | pending / accepted / rejected / revoked |
| 标签 / 热词 | 统一口径与快捷检索 | 字段映射、样式、启用状态 |

## 5. 端到端交付主流程

```text
登录
 → 建客户
 → 建项目 / 拆岗位（可 JD 智能解析预填）
 → 组长「分配权限」给操作员
 → 操作员在「任务看板」接受待办
 → 简历导入 或 Recruit 抓取入池 或 数据池检索（含 AI）
 → 「推荐至岗位」（自动锁定，每岗最多 10 人）
 → 「岗位候选人」页推进状态 + 写评价/跟踪
 → 候选人详情确认「已入职」
 → 「质保期管理」监控
 → 「统计管理」复盘
 → 「操作日志」审计（管理员）
```

### 6.5 岗位候选人管理

| 项 | 说明 |
|----|------|
| **用途** | 单岗位交付工作台：推进推荐状态、写评价、导出简历 |
| **入口** | 项目管理 / 客户预览 → `position-candidates.html?position_id=…` |

**功能介绍**

| 能力 | 介绍 |
|------|------|
| 岗位摘要 | 紧急程度、招聘人数、薪资、候选人/已推荐/已入职计数、JD 面板 |
| 筛选 | 姓名、流程状态、漏斗分桶、匹配度 |
| 候选人列表 | 联系方式、当前职位、城市、学历、经验、推荐状态 |
| 添加候选人 | 跳回数据池并带上岗位上下文 |
| 行内展开 | 候选人跟踪 + 评价 |
| 状态推进 | 更新推荐状态；移除推荐以释放锁定名额 |
| 导出 | 单人 / 批量导出 PDF 简历 |
| 详情弹窗 | 与数据池共用完整候选人详情能力 |

**推荐状态流转（示意）**

```text
待推荐 → 已推荐 → 客户已收 / 客户未收 → 安排面试
       → 拒绝 / 淘汰 / 未录用 / 已入职
```

**关键规则**

- 每岗位同时锁定候选人上限 **10** 人
- **已入职**候选人不可移除推荐关系

|----|------|
| **用途** | 猎头找人的核心工作台：检索、筛选、推荐、导出 |

**功能介绍**

| 能力 | 介绍 |
|------|------|

| 关键词搜索 | 空格为 AND，逗号/竖线为 OR；优先期望岗位，其次经历字段 |
| 条件筛选 | 期望城市（省市区）、学历、年龄、经验、排序、状态（已推荐/未锁定/已锁定/自己锁定/未面试等） |
| 猜你想搜 | 标签字典中的热词快捷过滤 |
| AI 检索 | 粘贴 JD，在当前列表内做 LLM 匹配 Top5 |
| 搜索方案 | 保存常用搜索条件，便于复用 |
| 列表操作 | 跨页多选、批量推荐至岗位、批量导出 PDF、分页 |
| 去重展示 | 按 PDF 文件名 / 手机 / 邮箱 / 姓名等规则去重 |
| 外部简历 | Recruit 来源通过关联展示；实质性操作触发「触碰即入库」 |

**候选人详情弹窗（多页共用）**

- 基本信息编辑、备注
- 候选人跟踪（面试记录 CRUD、初筛标记）
- 面试评价（等级与 1–5 分联动）
- 入职状态开关（已入职 / 未入职及原因）
- 发送邮件、入职后随访
- 推荐到项目/岗位、继续推荐其他岗位
- PDF 导出（可带合同号、项目号、猎头职位等信息）

## 7. 候选人三维状态与关键规则

系统用**三个维度**描述候选人，避免把「锁定」与「交付进度」混为一谈：

| 维度 | 字段含义 | 典型取值 | 谁驱动 |
|------|----------|----------|--------|
| 锁定 | 是否被岗位占用 | 未锁定 / 锁定 | **仅**由是否存在推荐关系决定，不可手工改 |
| 交付进度 | 推进到哪一步 | 未推荐 / 已推荐 / 面试中 / 未录用 / 已入职 | 推荐状态 + 面试跟踪联动 |
| 质保 | 入职后稳定期 | 空 / 质保中 / 质保到期 等 | 仅「已入职」且入职日期有效时计算 |

**关键硬规则（产品约束）**

1. 每个岗位最多同时锁定 **10** 名候选人。
2. **已入职**候选人的推荐关系不可移除。
3. 项目下全部岗位均达到「已入职人数 ≥ 招聘人数」时，项目自动「招聘完毕」。
4. 确认入职时需能解析出关联的公司与岗位信息。
5. 菜单与按钮按角色功能权限动态显示；写操作仍受数据权限与岗位接受状态约束。

## 8. 简历来源与隐式入库

系统采用**内外解耦 + 触碰即入库（懒加载）**：

1. 外部抓取程序只写入 `recruit` 相关表，不主动调用交付系统接口。
2. 数据池列表通过关联查询，把尚未入库的外部简历一并展示（来源可标为简历库等）。
3. 业务员对外部简历执行锁定、编辑、发信等实质性操作时，后端自动在本地业务库创建正式候选人记录，再继续完成该操作——用户无需点「导入」按钮。

手工 PDF 导入仍走「简历导入」模块，作为补录通道。
