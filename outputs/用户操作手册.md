# 猎头招聘交付系统 — 用户操作手册

> 版本说明：基于当前系统代码、`docs/prd/`、`outputs/招聘管理系统-业务流程总览.md` 与近期 `findings.md` 整理。  
> 适用对象：超级管理员、组长、操作员。  
> 系统定位：猎头公司内部岗位全生命周期管理（客户 → 项目 → 岗位 → 候选人推荐 → 面试 → 入职 → 质保）。

---

## 1. 快速入门

### 1.1 如何进入系统

1. 打开登录页（`login.html`）。
2. 输入账号、密码，点击「登录」。
3. 登录成功后进入「首页 / 数据看板」。

未登录访问业务页会自动跳转到登录页。

### 1.2 默认演示账号（本地环境）

| 角色 | 账号 | 密码 |
|------|------|------|
| 超级管理员 | `admin` | `admin123` |
| 组长 | `leader` | `leader123` |
| 操作员 | `operator` | `operator123` |

### 1.3 退出与单设备登录

- 侧栏底部点击「退出系统」即可登出。
- 同一账号在新设备登录后，旧设备会被踢下线，并提示「您的账号已在其他设备登录」。
- 被踢后需重新登录。

### 1.4 角色能做什么（摘要）

| 能力 | 超级管理员 | 组长 | 操作员 |
|------|:----------:|:----:|:------:|
| 用户 / 角色 / 权限 / 标签 / 质保配置 | ✅ | ❌ | ❌ |
| 新建客户、项目、岗位 | ✅ | ✅ | ❌ |
| 分配岗位给操作员 | ✅ | ✅ | ❌ |
| 简历池检索、导入、评价 | ✅ | ✅ | ✅ |
| 推荐 / 导出简历 | ✅ | ✅ | ✅（需已接受岗位分配） |
| 统计 | 全部 | 授权范围 | 个人数据 |
| 操作日志 | ✅ | ❌ | ❌ |

## 2. 日常交付主流程（必读）

推荐按下面顺序完成一次完整交付：

```text
登录
 → 建客户
 → 建项目 / 岗位
 → 组长分配岗位给操作员
 → 操作员在「任务看板」接受待办
 → 简历导入或从数据池找人
 → 推荐到岗位（锁定）
 → 岗位候选人页推进面试 / 评价
 → 确认已入职
 → 质保监控
 → 统计复盘
```

### 2.1 主流程检查表

| 步骤 | 页面 | 你要做的事 | 前置条件 |
|------|------|------------|----------|
| 1 | 登录 | 登录系统 | 账号已启用 |
| 2 | 客户管理 | 新建甲方客户 | 无 |
| 3 | 项目管理 | 在客户下建项目，再拆岗位 | 先有客户 |
| 4 | 项目管理 → 岗位 | 「分配权限」给操作员 | 岗位已创建；组长身份 |
| 5 | 任务看板 | 操作员「接受」岗位待办 | 已收到分配任务 |
| 6 | 简历导入 / 求职者数据池 | 补简历或检索候选人 | 无 |
| 7 | 求职者数据池 | 勾选候选人「推荐至岗位」 | 目标岗位已分配且已接受；岗位锁定未满 10 人 |
| 8 | 岗位候选人 | 推进状态、写评价、导出简历 | 已有推荐关系 |
| 9 | 候选人详情 | 滑动开关确认「已入职」 | 能解析出公司 + 岗位 |
| 10 | 质保期管理 | 查看质保中 / 到期候选人 | 已入职；管理员配置质保期 |
| 11 | 统计管理 | 查看漏斗与绩效 | 按角色数据范围 |

### 2.2 候选人状态怎么理解

系统用三个维度看候选人：

1. **锁定**：只要存在岗位推荐关系就是「已锁定」；不能手动锁定/解锁，只能通过「推荐」或「移除推荐」改变。
2. **交付进度**：未推荐 → 已推荐 → 面试中 → 未录用 / **已入职**。
3. **质保**：只有「已入职」后才有「质保中 / 质保到期」。

重要规则：

- 每个岗位最多同时锁定 **10** 名候选人。
- **已入职**候选人的推荐关系不能移除。
- 项目下每个岗位的「已入职人数」都达到招聘人数时，项目会变为「招聘完毕」。

## 4. 客户管理

**入口：** 侧栏「客户管理」

### 4.1 常见操作

| 操作 | 怎么做 |
|------|--------|
| 新建客户 | 点「新建客户」，填写公司名、联系人、电话等后保存 |
| 编辑 / 删除 | 在列表行内操作；删除前会二次确认 |
| 查看下属项目 | 点「项目」或相关指标，进入项目管理并按该公司过滤 |
| 预览岗位结构 | 点击客户名称，浮层展示项目 → 岗位，可点岗位进入岗位候选人页 |

### 4.2 注意

- 客户是主数据起点：**没有客户就不能建项目**。
- 创建 / 编辑 / 删除客户通常需要组长或管理员权限。

## 5. 项目管理（含岗位）

**入口：** 侧栏「项目管理」  
页面内有两个 Tab：**项目列表**、**岗位列表**。

### 5.1 项目列表

| 操作 | 说明 |
|------|------|
| 搜索 | 按名称、公司、状态、等级筛选 |
| 我的项目 | 勾选后只看「当前用户被分配岗位」所属的项目 |
| 新建项目 | 先选客户，再填项目名称、状态、等级、地点、周期等 |
| 编辑 / 删除 | 行内操作 |
| 查看岗位 | 点「岗位」或项目名称，进入该项目下的岗位视图 |

项目状态：

- 招聘中
- 招聘完毕
- 招聘中止

### 5.2 岗位列表

| 操作 | 说明 |
|------|------|
| 新建岗位 | 选择客户 → 项目，填写 JD、紧急程度、招聘人数、薪资区间、地点 |
| 编辑 / 删除 | 组长可见行内操作 |
| 分配权限 | 组长把岗位分配给直属操作员，生成待办任务 |
| 进入岗位候选人 | 点击岗位名称 |

### 5.3 岗位分配（协作关键）

1. 组长在岗位行点击「分配权限」，选择操作员。
2. 操作员打开「任务看板」，对待办选择「接受」或「拒绝」。
3. **只有接受后**，操作员才能对该岗位做推荐、导出等写操作。

## 6. 求职者数据池

**入口：** 侧栏「求职者数据池」

这是日常找人、推荐、导出的主工作台。

### 6.1 搜索语法（必记）

| 写法 | 含义 | 示例 |
|------|------|------|
| 空格 | 且（AND） | `Java 北京` = 同时含 Java 且含北京 |
| 逗号 / 竖线 | 或（OR） | `Java,Spring` 或 `Java\|Spring` |
| 组合 | 组内或 + 组间且 | `Java,Spring 北京` = (Java 或 Spring) 且 北京 |

搜索会覆盖姓名、手机、邮箱、职位、城市、工作经历、项目、证书、标签等全文。

### 6.2 常用筛选

- 期望城市、学历、年龄、经验
- 状态：未锁定 / 已锁定 / 自己锁定 / 未面试
- 指标卡：总数、今日新增、已锁定（点击可过滤）
- 排序：默认 / 更新时间 / 年龄
- 可保存当前搜索方案，方便下次复用

### 6.3 推荐与导出

| 操作 | 步骤 |
|------|------|
| 推荐至岗位 | 勾选候选人 →「推荐至岗位」→ 选择目标岗位 → 确认 |
| 批量推荐 | 同上；无权限、已重复、超限的项会跳过并汇总提示 |
| 导出简历 | 勾选后填写合同号 / 项目号 / 猎头职位等信息，生成 PDF 下载 |

### 6.4 锁定规则

- 推荐成功后自动锁定，**不能在详情里手动改锁定**。
- 未锁定候选人：有目标岗位权限即可推荐。
- 已锁定候选人：需通过归属 / 权限校验。
- 同岗位锁定满 10 人后，需先在岗位候选人页「移除」未入职候选人，才能继续推荐。

### 6.5 列表去重说明

- 优先按简历 PDF 文件名归并展示。
- 无附件时回退按手机 / 邮箱 / 姓名识别同一人。
- 因此同一人多次投递同名 PDF，列表通常只显示一条。

## 7. 简历导入

**入口：** 侧栏「简历导入」

| 操作 | 说明 |
|------|------|
| 单份导入 | 选择 PDF 文件导入 |
| 批量导入 | 一次选择多个 PDF，逐个处理 |

## 8. 岗位候选人管理

**入口：** 项目管理 → 点击岗位名称  
（或客户预览浮层中点击岗位）

### 8.1 页面能做什么

| 操作 | 说明 |
|------|------|
| 添加候选人 | 跳回数据池，带上当前岗位做推荐 |
| 搜索筛选 | 按姓名、流程状态、匹配度等过滤 |
| 展开行 | 查看跟踪记录与评价 |
| 推进 | 按状态机更新推荐 / 面试进度 |
| 导出简历 | 单人或批量导出 |
| 移除 | 删除推荐关系并释放锁定名额 |

### 8.2 注意

- 已入职候选人**不可移除**。
- 推进状态后，评价、入职、质保才能继续接上。
- 返回可用浏览器返回，或从项目管理重新进入。

## 9. 候选人详情（多页共用）

在数据池、岗位候选人、质保页打开详情后，通常可以：

| 模块 | 操作 |
|------|------|
| 基本信息 | 编辑候选人资料 |
| 备注 | 添加备注 |
| 候选人跟踪 | 新增 / 编辑 / 删除面试与沟通记录 |
| 评价记录 | 新增 / 编辑 / 删除轮次评价 |
| 入职状态 | 滑动开关确认「已入职」；切回「未入职」需填写原因 |
| 发送邮件 | 记录邮件发送 |
| 随访 | 仅已入职后可用 |
| 推荐项目 | 查看历史推荐，也可继续推荐到其他岗位 |

### 9.1 确认已入职的注意点

标记「已入职」时，系统需要能解析出**公司 + 岗位**。解析顺序大致为：

1. 约定薪资记录  
2. 面试评价关联岗位  
3. 推荐岗位  
4. 当前页岗位（如从岗位候选人页进入）

若提示无法确认入职，请先补齐评价或从对应岗位页进入详情再操作。

## 14. 平台岗位发布（Recruit 抓取）

与「交付项目岗位」不同，这里配置的是给外部抓取程序用的岗位条件。

### 14.1 岗位发布

**入口：** 平台岗位发布 → 岗位发布

填写岗位名称、地点、年龄、学历、活跃时间、每日打招呼上限、搜索关键词等，并设置是否参与抓取（有效 / 跳过）。

### 14.2 岗位列表

查看、编辑、删除已发布的抓取岗位；可按有效状态筛选。

### 14.3 每日任务

按日期查看打招呼、索要简历、下载、回执等抓取统计。

简历入池链路简述：

```text
发布抓取岗位 → 外部程序抓取下载 → AI 解析 → 出现在求职者数据池
```

## 15. 系统设置（管理员）

### 15.1 用户管理

- 创建用户（用户名、姓名、角色、直属组长、初始密码等）

### 15.2 角色管理

### 15.3 权限管理

- 查看功能权限矩阵
- 调整某权限关联的角色
- 查看数据权限规则说明

### 15.4 数据权限

- 给组长分配公司级范围
- 给操作员分配公司 / 项目 / 岗位粒度范围
- 移除或停用已分配权限

说明：岗位「分配权限」任务流与数据权限联动，是操作员实际开展推荐工作的前置。

### 15.5 标签字典

- 按候选人 / 岗位 / 项目 / 客户维护标签字段与样式

### 15.6 操作日志

- 按模块、操作人、关键词、日期筛选
- 可导出 CSV
- 用于审计导入、推荐、权限变更等关键动作

### 15.7 AI 能力中心 / 系统配置

- AI 能力中心：简历解析、JD 生成、匹配等任务入口（当前大模型为 DeepSeek）
- 系统配置：系统名称、水印、邮件 SMTP 等

这两个页面可能不在侧栏常驻入口，需要直接访问对应页面或从相关跳转进入。

## 16. 按角色的日常工作清单

### 16.1 操作员

1. 登录后先看「任务看板」，接受岗位分配。
2. 在「求职者数据池」按关键词找人。
3. 推荐到已接受的岗位。
4. 在「岗位候选人」推进面试、写评价。
5. 条件成熟后确认入职。
6. 关注通知与个人相关统计。

### 16.2 组长

1. 维护客户、项目、岗位。
2. 把岗位分配给操作员，并跟踪接受情况。
3. 关注团队推荐日历、待办与统计。
4. 必要时协助推进、复核评价与交付结果。

### 16.3 超级管理员

1. 维护用户、角色、功能权限、数据权限。
2. 配置标签字典与质保期。
3. 监控质保到期与操作日志。
4. 管理平台岗位发布与系统级配置。

## 17. 常见问题

### Q1：为什么我不能推荐候选人？

请依次检查：

1. 是否已登录且账号启用。
2. 目标岗位是否已分配给你，并且你已在任务看板「接受」。
3. 该岗位锁定人数是否已满 10。
4. 候选人是否已被其他人锁定且你无权限。

### Q2：为什么无法标记已入职？

系统需要识别公司与岗位。请从对应岗位候选人页进入详情，或先补齐评价 / 约定薪资中的岗位信息。

### Q3：为什么搜索不到刚导入的简历？

- 刷新数据池列表。
- 检查搜索词是否过严（空格是「且」，会缩小结果）。
- 若导入进入待复核，先处理复核结果。

### Q4：为什么突然被退出登录？

账号可能在其他设备登录，触发了单设备互踢。重新登录即可；如非本人操作，请联系管理员重置密码。

### Q5：项目什么时候变成「招聘完毕」？

当该项目下每个岗位的「已入职人数」都达到该岗位招聘人数时，项目会同步为「招聘完毕」。

### Q6：平台岗位发布和项目管理里的岗位有什么区别？

| 类型 | 用途 |
|------|------|
| 项目管理中的岗位 | 交付管理：推荐、面试、入职、质保 |
| 平台岗位发布 | 给外部抓取程序用的搜索条件与任务统计 |

## 19. 附录：推荐培训顺序

新同事建议按下面顺序上手：

1. 登录 / 退出 / 被踢提示  
2. 客户 → 项目 → 岗位  
3. 岗位分配与任务接受  
4. 数据池搜索语法与推荐  
5. 岗位候选人推进与评价  
6. 确认入职与质保查看  
7. 通知与统计  
8.（管理员）用户权限与日志  

完成以上路径，即覆盖系统从接单到质保的主闭环。
